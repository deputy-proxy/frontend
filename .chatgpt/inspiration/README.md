# Inspiration Library

This folder is the design-direction library for the frontend authoring workflow.

The files here describe **visual and interaction directions**, not reusable page templates. They exist to prevent every generated website from converging on the same familiar arrangement of hero, oversized headline, image split, cards, and polite little gradients.

## How the author uses this library

When creating a new page, the author should:

1. Read the available inspiration files before choosing a visual direction.
2. Select one or two directions that fit the business, audience, content, and brand context.
3. Reinterpret the selected principles rather than copying a reference literally.
4. Cross-check the existing `originals/` pages and deliberately avoid repeating their dominant visual patterns.
5. Let the business brief determine the final result. Inspiration is a constraint against repetition, not a requirement to imitate a style.

The user should **not** need to provide a separate style input. The author infers an appropriate direction from the business brief and the available library.

## What makes a useful inspiration file

Each inspiration file should describe a coherent design language across:

- visual character and overall mood
- layout and spatial composition
- typography and type hierarchy
- color strategy
- navigation and header behavior
- hero composition
- section rhythm and content sequencing
- grids, cards, borders, surfaces, and other UI patterns
- imagery, illustration, or graphic treatment
- interaction and motion principles
- responsive behavior
- appropriate business/content contexts
- patterns to avoid so the direction stays distinctive

Describe **principles and decisions**, not implementation code.

## Design diversity requirement

The author should vary several independent dimensions between projects, including:

- page composition
- hero structure
- typography pairing
- color system
- image treatment
- navigation pattern
- section rhythm
- card/surface language
- decorative system
- motion language

A new page should not merely change colors while preserving the same underlying composition.

## Recommended file naming

Use short, descriptive kebab-case names, for example:

- `brutalist-editorial.md`
- `swiss-systematic.md`
- `luxury-studio.md`
- `technical-interface.md`
- `organic-modern.md`
- `maximalist-culture.md`

Keep each direction meaningfully different from the others. The goal is a useful design vocabulary, not a warehouse of near-duplicates.
